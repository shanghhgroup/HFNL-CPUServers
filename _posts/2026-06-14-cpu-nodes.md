## 1. 概述

ShangGroup 服务器提供面向科研计算的 CPU 计算资源，适合运行量子化学、AFQMC/QMC、数值模拟、程序编译、批量数据处理等 CPU 密集型任务。

## 2. CPU 资源公开说明

| 项目 | 公开说明 |
|---|---|
| 资源类型 | 多核 CPU 科学计算资源 |
| 主要任务 | 量子化学、QMC、数值模拟、编译测试、数据处理 |
| 运行方式 | 通过 Slurm 作业脚本提交 |
| 并行方式 | 支持常见 CPU 并行程序，如 MPI / OpenMP / 多进程 Python |
| 内存使用 | 可支持一般科研计算任务，具体可用额度以内部规则为准 |
| 节点细节 | 不在公开网页展示，按内部说明查询 |

## 3. 节点角色说明

| 角色 | 用途 | 使用建议 |
|---|---|---|
| 登录环境 | 登录、编辑脚本、整理文件、提交作业 | 只运行轻量命令和小规模测试 |
| 计算资源 | 承担正式计算任务 | 通过 Slurm 申请资源后运行 |
| 存储空间 | 保存输入、输出和中间文件 | 按项目分类整理，避免长期堆积临时文件 |

登录环境可能同时承担管理或调度相关功能，因此不要在交互式登录会话中直接运行长时间高负载任务。

## 4. CPU 并行任务建议

对于 CPU 任务，建议按以下顺序逐步测试：

| 阶段 | 建议做法 | 目的 |
|---|---|---|
| 小规模测试 | 使用少量核心、短时间运行 | 检查程序、输入和环境是否正确 |
| 单节点测试 | 在单个计算资源范围内扩大核数 | 观察 CPU 利用率和内存占用 |
| 批量运行 | 稳定后提交正式任务 | 获得完整结果 |
| 大任务申请 | 长时间或大规模任务提前沟通 | 避免影响其他用户 |

对于内存带宽敏感、强通信 MPI 或大量 I/O 的程序，建议先做小规模性能测试，再决定是否扩大资源申请。

## 5. Slurm 分区与资源申请

本页面不展示具体分区名称和资源上限。组内用户提交任务时，请以内部说明为准，把下面脚本中的 `<partition_name>` 替换为实际可用分区。

查看可用分区和节点状态：

```bash
sinfo
```

查看自己正在排队或运行的任务：

```bash
squeue -u $USER
```

## 6. CPU 作业脚本示例

示例脚本 `cpu_test.sh`：

```bash
#!/bin/bash
#SBATCH -J test_cpu
#SBATCH -p <partition_name>
#SBATCH -N 1
#SBATCH -n 4
#SBATCH -o %j.log
#SBATCH -e %j.err

set -e

echo "Job ID: $SLURM_JOB_ID"
echo "Partition: $SLURM_JOB_PARTITION"
echo "Node list: $SLURM_JOB_NODELIST"
echo "Submit dir: $SLURM_SUBMIT_DIR"
echo "Start time: $(date)"

cd "$SLURM_SUBMIT_DIR"

# 将下面命令替换成你的 CPU 程序
srun hostname

echo "End time: $(date)"
```

提交任务：

```bash
sbatch cpu_test.sh
```

查看任务：

```bash
squeue -u $USER
```

取消任务：

```bash
scancel JOBID
```

## 7. 正式计算前检查

建议在扩大任务规模前确认：

- 程序能在小输入上正常运行；
- 日志中没有明显错误；
- 输入文件路径正确；
- 输出目录空间充足；
- 并行参数与申请资源一致；
- 长任务有必要的 checkpoint 或可恢复机制。
