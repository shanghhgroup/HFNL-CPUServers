## 1. 存储概况

服务器提供科研数据存储空间，用于保存输入文件、输出结果、脚本、日志和中间数据。页面不展示真实挂载点、磁盘容量、NFS 配置、导出规则、内部路径和网络拓扑。

组内用户应按照内部说明选择合适目录存放数据，不要把大规模计算数据长期堆放在系统盘或公共临时目录中。

## 2. 使用建议

- 大型输入、输出和中间文件应放在指定数据目录；
- 不建议把大规模计算数据长期放在系统盘或 home 目录；
- 大文件计算前建议确认磁盘剩余空间；
- 大量小文件会增加文件系统压力，建议按任务建立独立目录；
- 重要结果应及时备份到本地或课题组长期存储位置；
- 不要删除公共数据、他人目录或管理员维护的软件目录。

查看磁盘空间：

```bash
df -h
```

查看当前目录占用：

```bash
du -sh .
```

查看某个项目目录下文件大小：

```bash
du -h --max-depth=1 ./project_name | sort -h
```

## 3. 网络说明

服务器网络用于登录、文件传输、作业调度和计算节点之间的数据访问。页面不展示真实 IP、网段、网卡名称、端口、内部互联方式、跳板机或 VPN 信息。

对普通用户来说，最重要的是：

| 场景 | 建议 |
|---|---|
| 登录服务器 | 按内部 SSH / VPN / 跳板机说明操作 |
| 上传下载文件 | 使用 `scp`、Xftp、MobaXterm 或 VS Code 远程工具 |
| 大文件传输 | 避开高峰时段，传输后核对文件完整性 |
| 多节点任务 | 先做小规模性能测试，再扩大规模 |
| 频繁 I/O 程序 | 减少不必要读写，按项目组织目录 |

## 4. 对计算任务的影响

对多数单节点 CPU 计算任务，网络影响通常较小，例如：

- 单节点 OpenMP 程序；
- 单节点 Python / C++ / Fortran 计算；
- 单节点量子化学计算；
- 中小规模数据分析。

对以下任务需要谨慎：

- 强通信多节点 MPI；
- 多节点同时读写同一批大文件；
- 大量小文件频繁写入共享目录；
- 高频 checkpoint 写入公共数据空间。

如果程序支持，建议将临时文件写入任务专属目录，计算结束后再整理输出结果。

## 5. 目录组织建议

建议每个用户按项目建立目录：

```text
project_name/
├── input/
├── scripts/
├── logs/
├── results/
└── tmp/
```

这样方便定位日志、清理临时文件和向管理员反馈问题。

## 6. 数据安全建议

- 重要结果至少保留一份异地备份；
- 定期清理临时文件和失败任务输出；
- 不要把敏感数据、账号密码或密钥写入脚本；
- 不要把内部路径和目录截图直接发布到公开网络；
- 共享数据前确认是否涉及未发表结果或课题组内部资料。
