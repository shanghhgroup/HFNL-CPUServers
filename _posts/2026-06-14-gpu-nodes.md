## 1. 说明

本页面不列出实验室 GPU 资源的具体有无、型号、数量、显存、驱动版本、CUDA 版本或 Slurm GRES 配置。涉及 GPU 的内部配置可能随维护和采购情况变化，组内用户提交 GPU 作业前应先查看内部说明或联系管理员确认。

## 2. GPU 任务提交前需要确认

| 需要确认的项目 | 说明 |
|---|---|
| 是否有可用 GPU 资源 | 不同服务器和分区配置可能不同 |
| GPU 分区名称 | 以内部 Slurm 说明为准 |
| GPU 申请参数 | 例如是否需要 `--gres` 或其他资源参数 |
| CUDA / 驱动环境 | 以管理员维护的环境为准 |
| 深度学习框架 | PyTorch / TensorFlow 等版本需与 CUDA 匹配 |
| 作业时间限制 | 长时间训练任务应提前确认 |

## 3. GPU 作业脚本通用模板

以下模板仅作为写法示例，具体分区名、GPU 数量和模块名称请按内部说明修改。

```bash
#!/bin/bash
#SBATCH -J gpu_job
#SBATCH -p <gpu_partition>
#SBATCH -N 1
#SBATCH -n 4
#SBATCH --gres=gpu:1
#SBATCH -o %j.log
#SBATCH -e %j.err

set -e

cd "$SLURM_SUBMIT_DIR"

echo "Job ID: $SLURM_JOB_ID"
echo "Node list: $SLURM_JOB_NODELIST"
echo "Start time: $(date)"

# 如果内部环境要求加载 CUDA 或 Conda，请在这里加载
# module load <cuda_module>
# conda activate <env_name>

python train.py

echo "End time: $(date)"
```

## 4. 没有 GPU 资源时怎么办？

如果当前可用服务器没有 GPU 资源，仍可运行：

- CPU 版本的预处理和后处理脚本；
- 小规模模型调试；
- 不依赖 CUDA 的科学计算程序；
- 使用 CPU 后端的 PyTorch / NumPy / SciPy 程序；
- 将训练任务转移到组内其他 GPU 服务器或合作平台。
